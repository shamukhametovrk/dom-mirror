# dom-mirror (прототип)

Браузер на сервере, но вместо видео пользователю передаётся **копия страницы** (HTML и CSS).
На сервере работает обычный Google Chrome с окном на виртуальном экране (не headless, без флагов
автоматизации, с постоянным профилем — входы в аккаунты сохраняются). [rrweb](https://github.com/rrweb-io/rrweb)
записывает DOM и его изменения, браузер пользователя собирает из них копию. Клики, прокрутка и клавиши уходят
обратно на сервер. Картинки, шрифты и стили тоже идут через сервер, сайт видит только его IP.

Как устроено и почему — [docs/architecture.md](docs/architecture.md).

## Запуск

```sh
docker compose up -d --build
```

Откройте http://localhost:8095. Адрес меняется в строке сверху.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `START_URL` | `https://ru.wikipedia.org/` | Стартовая страница |
| `HTTP_PORT` | `8095` | Порт на хосте |
| `TZ` | `Europe/Moscow` | Часовой пояс; должен совпадать с местоположением IP сервера |
| `ACCEPT_LANGUAGES` | `ru-RU,ru,en-US,en` | Языки браузера; сохраняются в профиле |
| `FRAMES` | `1` | `0` отключает показ cross-origin iframe картинкой |
| `SETTLE_MS` | `80` | Пауза после снимка iframe, чтобы Chrome не терял клики |

Отладка: `/debug/shot.png` (снимок серверного браузера), `/debug/state` (поля ввода), `/debug/stats` (откуда берутся ресурсы).

## Разработка

```sh
npm install
npm run check      # линтер, проверка типов, тесты
```

Сервер можно запустить и без Docker, подключив его к любому Chrome с `--remote-debugging-port`:

```sh
CDP_URL=http://127.0.0.1:9222 PORT=8095 npm start
```

## Что умеет прототип

- показывать страницу и её изменения в реальном времени;
- клики, прокрутка, ввод с клавиатуры (в том числе горячие клавиши на русской раскладке), вставка текста;
- навигация: адресная строка, назад/вперёд, обновить; новые вкладки открываются на месте;
- iframe с чужих сайтов (в том числе виджеты «я не робот») показываются живой картинкой, клики доходят.

## Ограничения

- один общий браузер на всех подключившихся;
- профиль Chrome хранится в volume `chrome-profile`; `docker compose down -v` его удалит;
- canvas, видео и WebGL не передаются;
- rrweb не видит правила, добавленные через `insertRule` после загрузки, и значения полей, выставленные
  скриптом без события; в начальный снимок они попадают;
- сложные поля ввода и редакторы могут вести себя странно;
- попапы входа (OAuth) открываются в основной вкладке, поэтому `window.opener` не работает.

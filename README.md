# dom-mirror (прототип)

Браузер на сервере, но вместо видео пользователю передаётся **копия страницы** (HTML и CSS).
На сервере работает обычный Google Chrome с окном на виртуальном экране (не headless, без флагов
автоматизации, с постоянным профилем — входы в аккаунты сохраняются). Chrome открывает сайт, [rrweb](https://github.com/rrweb-io/rrweb) записывает DOM и все его
изменения, браузер пользователя собирает из них копию. Клики, прокрутка и клавиши уходят обратно
на сервер. Картинки, шрифты и стили тоже идут через сервер, сайт видит только его IP.

## Запуск

```sh
docker compose up -d --build
```

Откройте http://localhost:8095. Адрес меняется в строке сверху.

## Что умеет прототип

- показывать страницу и её изменения в реальном времени;
- клики, прокрутка, ввод с клавиатуры, вставка текста;
- навигация: адресная строка, назад/вперёд, обновить; новые вкладки открываются на месте.

## Меньше антибот-проверок

- WebGL включён (программный SwiftShader), как у обычного десктопного Chrome.
- Часовой пояс и языки задаются переменными `TZ` (по умолчанию `Europe/Moscow`) и `ACCEPT_LANGUAGES`;
  они должны совпадать с местоположением IP сервера. Языки сохраняются в профиле Chrome.
- rrweb и его функции связи работают в изолированном мире Chrome: страница не видит `window.rrweb`,
  глобальных переменных и подменённых прототипов.
- Playwright не используется: сервер говорит с Chrome напрямую по CDP ([cdp.js](cdp.js)) и не включает
  домен Runtime. События из страницы забираются опросом очереди в изолированном мире.
- Картинки, шрифты и стили для копии берутся у самого Chrome, а не у Node: сначала отдаются ответы, которые
  Chrome уже загрузил для настоящей страницы (`Network.getResponseBody`), затем ресурс скачивает сам Chrome
  (`Network.loadNetworkResource`), и только в крайнем случае (строгий CSP у сайта) грузит Node. Счётчики:
  `/debug/stats`.
- Клавиши приходят в страницу раздельно (нажатие и отпускание) с настоящими `code`/`keyCode` и временем
  пользователя, горячие клавиши работают на русской раскладке. Ход мыши — около 60 раз в секунду,
  отпускание кнопки за пределами окна не теряется.
- iframe с чужих сайтов (в том числе виджеты проверки «я не робот») показываются живой картинкой
  своей области (до 4 кадров в секунду), клики по ней доходят до настоящей страницы. Пока вы двигаете мышь или
  печатаете, кадры не снимаются, а после каждого снимка идёт пауза `SETTLE_MS` (80 мс): иначе Chrome
  иногда терял клик. `FRAMES=0` отключает показ iframe совсем.

## Ограничения

- один общий браузер на всех подключившихся;
- профиль Chrome хранится в volume `chrome-profile`; `docker compose down -v` его удалит;
- canvas, видео и WebGL не передаются;
- из-за изолированного мира rrweb не видит правила, которые страница добавляет через `insertRule`
  после загрузки, и значения полей, выставленные скриптом без события; в начальный снимок они попадают;
- сложные поля ввода и редакторы могут вести себя странно;
- сайты, у которых часть интерфейса в iframe, отображаются не полностью.

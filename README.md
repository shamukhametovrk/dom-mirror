# dom-mirror

Браузер на сервере, который вы открываете у себя как обычную вкладку. Вместо видеопотока передаётся **копия страницы**
(HTML и CSS): текст остаётся чётким, выделяется и копируется, трафика нужно мало, а сайт видит только IP сервера.

На сервере работает обычный Google Chrome с окном на виртуальном экране — не headless, без флагов автоматизации,
с постоянным профилем, так что входы в аккаунты сохраняются. [rrweb](https://github.com/rrweb-io/rrweb) записывает
DOM и его изменения, ваш браузер собирает из них копию, а клики, прокрутка и клавиши уходят обратно на сервер.

- Копия страницы в реальном времени, ввод с клавиатуры (и горячие клавиши на русской раскладке), вставка текста.
- Адресная строка, назад/вперёд, обновить. Новые вкладки открываются на месте.
- iframe с чужих сайтов (виджеты «я не робот», видео) показываются живой картинкой, клики по ним работают.
- Картинки, шрифты и стили идут через сервер: ваш IP сайту не виден.
- Вход по паролю, профиль Chrome сохраняется между перезапусками.

Как устроено внутри — [docs/architecture.md](docs/architecture.md).

## Быстрый старт

1. **Сервер.** Linux x86-64 (amd64) с публичным IP. Подойдёт любой VPS: Hetzner, DigitalOcean, Contabo, Vultr и т.п.
   Часовой пояс и язык браузера лучше выбрать под страну сервера (см. [Настройка](#настройка)).

   | Ядра | Память | Как будет работать |
   |---|---|---|
   | 1 | 1 ГБ | Не рекомендуется: контейнер с одной большой страницей уже занимает ~0,7 ГБ |
   | 2 | 2 ГБ | Нормально для обычного сёрфинга |
   | 4 | 4 ГБ | Рекомендуется: тяжёлые сайты, веб-приложения, несколько переходов подряд |

   В покое сервис почти не нагружает процессор (~3% одного ядра); нагрузка растёт, пока страница меняется.

2. **Docker.** Подключитесь по SSH и поставьте Docker с плагином Compose:

   ```sh
   curl -fsSL https://get.docker.com | sh
   ```

3. **Код и настройки.**

   ```sh
   git clone <адрес репозитория> dom-mirror
   cd dom-mirror
   cp .env.example .env
   ```

   Откройте `.env` и задайте хотя бы `PASSWORD`, `TZ` и `ACCEPT_LANGUAGES`. Если пароль оставить пустым,
   он сгенерируется сам.

4. **Запуск.** Первая сборка занимает несколько минут: скачиваются Chrome и шрифты.

   ```sh
   docker compose up -d --build
   ```

5. **Вход.** Откройте `http://<IP сервера>:8095` и введите пароль. Если вы его не задавали:

   ```sh
   docker compose exec dom-mirror cat /data/password
   ```

> Без HTTPS пароль и всё, что вы вводите, идут по сети открытым текстом. Для доступа через интернет поставьте
> перед сервисом обратный прокси с TLS — это пара строк, см. [Обратный прокси](#обратный-прокси).

## Управление

| Действие | Команда |
|---|---|
| Логи | `docker compose logs -f` |
| Остановить | `docker compose down` |
| Перезапустить браузер | `docker compose restart` |
| Обновить до новой версии | `git pull && docker compose up -d --build` |
| Посмотреть пароль | `docker compose exec dom-mirror cat /data/password` |
| Сменить пароль | задать `PASSWORD` в `.env`, затем `docker compose up -d` — все сессии сбросятся |
| Стереть профиль (входы, cookies, пароль) | `docker compose down -v` |

Состояние контейнера видно в `docker compose ps`: встроенная проверка опрашивает `/health` раз в 30 секунд.
Если Chrome упал, контейнер завершится и перезапустится сам.

## Настройка

Переменные задаются в `.env` рядом с `docker-compose.yml`. После изменения: `docker compose up -d`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PASSWORD` | *(генерируется)* | Пароль для входа. Пусто — создаётся при первом запуске и хранится в `/data/password` |
| `HTTP_PORT` | `8095` | Порт на хосте |
| `HTTP_BIND` | `0.0.0.0` | Интерфейс хоста. За обратным прокси на той же машине — `127.0.0.1` |
| `START_URL` | `https://ru.wikipedia.org/` | Страница, которая открывается при запуске |
| `TZ` | `Europe/Moscow` | Часовой пояс браузера. Должен совпадать со страной IP сервера |
| `ACCEPT_LANGUAGES` | `ru-RU,ru,en-US,en` | Языки браузера (`navigator.languages` и `Accept-Language`) |
| `TRUST_PROXY` | `0` | `1` — сервис за обратным прокси: доверять `X-Forwarded-Proto` и `X-Forwarded-Host` |
| `FRAMES` | `1` | `0` — не показывать iframe с чужих сайтов картинкой |
| `DEBUG` | `0` | `1` — писать в лог типы входящих сообщений (без содержимого) |

Для тонкой настройки есть ещё `SETTLE_MS` (пауза после снимка iframe, по умолчанию `80`).

**Почему важны `TZ` и `ACCEPT_LANGUAGES`.** Сайты сравнивают часовой пояс и язык браузера с местоположением IP.
Сервер в Германии с московским временем выглядит подозрительно, и проверок «я не робот» становится больше.

## Обратный прокси

Прокси даёт HTTPS и нормальный адрес вместо `IP:8095`. В `.env` для этого:

```sh
TRUST_PROXY=1
HTTP_BIND=127.0.0.1   # если прокси на той же машине — порт снаружи не нужен
```

Сервис работает через WebSocket `/ws`, прокси должен его пропускать. Сервер шлёт ping каждые 25 секунд,
так что стандартных таймаутов хватает.

### Caddy

Проще всего: сертификат Let's Encrypt получается сам, WebSocket работает без настроек.

```caddyfile
browser.example.com {
    reverse_proxy 127.0.0.1:8095
}
```

### nginx

```nginx
server {
    listen 443 ssl http2;
    server_name browser.example.com;
    # ssl_certificate / ssl_certificate_key — например, от certbot

    location / {
        proxy_pass http://127.0.0.1:8095;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 1h;
    }
}
```

### Traefik

Добавьте сервису метки в `docker-compose.yml` (и подключите его к сети Traefik):

```yaml
    labels:
      - traefik.enable=true
      - traefik.http.routers.dom-mirror.rule=Host(`browser.example.com`)
      - traefik.http.routers.dom-mirror.entrypoints=websecure
      - traefik.http.routers.dom-mirror.tls.certresolver=letsencrypt
      - traefik.http.services.dom-mirror.loadbalancer.server.port=8080
```

Публиковать порт (`ports:`) в этом случае не обязательно.

## Безопасность

- **Браузер общий.** Все, кто знает пароль, управляют одним Chrome с одними входами в аккаунты.
  Не давайте пароль тем, кому не доверили бы свой браузер.
- **Профиль — это ваши сессии.** Том `chrome-profile` содержит cookies и сохранённые входы. Берегите его так же,
  как пароли.
- **Нужен HTTPS** при доступе через интернет, иначе пароль и ввод перехватываются (см. [Обратный прокси](#обратный-прокси)).
- **Что защищено:** вход по паролю (cookie `HttpOnly`, `SameSite=Strict`, при HTTPS — `Secure`); WebSocket принимает
  подключения только со своего адреса; прокси ресурсов отдаёт лишь адреса, подписанные сервером, — открытым
  прокси он не служит; неверный пароль задерживает ответ на секунду; введённый текст в логи не пишется.
- Отладочные адреса `/debug/shot.png`, `/debug/state` (значения полей ввода!) и `/debug/stats` доступны только после входа.
- Chrome запускается с `--no-sandbox` внутри контейнера: изоляцию обеспечивает сам контейнер.

## Решение проблем

**«нет связи» в правом верхнем углу.** Сервис перезапускается или WebSocket не проходит через прокси. Проверьте
`docker compose ps` и логи; для nginx — заголовки `Upgrade`/`Connection` из примера выше.

**Открывается страница входа по кругу.** За прокси с HTTPS не задан `TRUST_PROXY=1`, либо прокси не передаёт
`X-Forwarded-Proto`.

**Пустая страница вместо сайта.** Посмотрите, что видит серверный браузер: `https://<адрес>/debug/shot.png`
(после входа). Если там тоже пусто — сайт ещё грузится или упал Chrome (`docker compose logs`).

**Сайт часто просит «я не робот».** Проверьте, что `TZ` и `ACCEPT_LANGUAGES` соответствуют стране IP. Помогает
и вход в аккаунт Google в серверном браузере: профиль сохраняется.

**Забыл пароль.** `docker compose exec dom-mirror cat /data/password` — если он генерировался. Если задан в `.env`,
он там же.

**Сервер на ARM (Raspberry Pi, Oracle Ampere).** Не поддерживается: Google не выпускает Chrome для Linux ARM.

**Нужно начать с чистого профиля.** `docker compose down -v && docker compose up -d` — удалятся все входы
и сгенерированный пароль.

## Ограничения

- Один общий браузер на всех подключившихся; размер окна подстраивается под последнего.
- canvas, видео и WebGL внутри страницы не передаются (кроме iframe с чужих сайтов, которые идут картинкой).
- Правила стилей, добавленные скриптом через `insertRule` после загрузки, и значения полей, выставленные скриптом
  без события, могут не попасть в копию.
- Сложные редакторы (Google Docs и т.п.) работают с ограничениями.
- Попапы входа (OAuth) открываются в основной вкладке, поэтому `window.opener` не работает.

## Разработка

```sh
npm install
npm run check      # линтер, проверка типов, тесты
```

Без Docker сервер подключается к любому Chrome, запущенному с `--remote-debugging-port`:

```sh
CDP_URL=http://127.0.0.1:9222 PORT=8095 npm start
```

Пароль в этом режиме хранится в `.data/password`.
